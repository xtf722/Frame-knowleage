# 08 从通知栏与平板适配理解 Flutter 约束

[课程入口](README.md) · [本期来源](../evidence/app-october-source-map.md#layout) · [下一期](09-time-and-capabilities.md)

阅读快照：2026-10-26。案例来自 10 月的平板适配与 Notifications 标题栏修复。学完应能解释：同样一个 `Row`，为什么在手机上正常，放进平板窄面板或开启大字号后就会出问题。

先修：[Widget 与 State](../beginner/05-widget-state.md)。本期只追一个问题：**组件真正能用的空间由谁决定？**

## 从一个实际冲突开始

通知面板的标题、批量已读动作和关闭按钮需要共存。标题变长、按钮进入处理中状态或系统字号变大时，可用空间会变少。把所有文字缩小虽然可能消除溢出，却损害可读性；把整个标题栏放进横向滚动，关闭按钮又可能被带出视口。

当前实现将关闭按钮留在外层 `Row`，把标题和批量动作放进 `Expanded` 内的局部横向滚动区。详情态显示返回入口，列表态不保留空的返回占位。这是一项空间职责分配：哪些内容可移动、哪些操作必须一直可达。

## 约束比设备名称更可靠

Flutter 布局中，父级向下传约束，子级在约束内决定尺寸，父级决定位置。`width: 400` 表达期望，不能越过父级给定的最大宽度。[Flutter 约束说明](https://docs.flutter.dev/ui/layout/constraints)

| 输入 | 回答的问题 | 容易误用的地方 |
| --- | --- | --- |
| `MediaQuery.sizeOf(context)` | 当前窗口多大 | 当成嵌套面板还能使用的尺寸 |
| `LayoutBuilder` 的 `constraints` | 当前父级允许多大 | 把滚动方向上的无界高度当剩余高度 |
| `safeAreaPadding` | 系统遮挡需要避开多少 | 外层已处理后再次扣除 |
| `viewInsets` | 键盘等遮挡占多少 | Scaffold 已调整后再次减掉整段高度 |
| `TextScaler` | 系统如何缩放文字 | 用整体页面缩放抵消用户字号设置 |

项目的 `AppAdaptiveLayout` 是共享布局能力的 App 薄封装。`AppLayoutInfo.heightSource` 区分父约束和窗口回退；窗口回退值不能证明固定底部按钮上方还剩那么多空间。`BesideYouAdaptiveMetrics` 同时考虑窗口短边与局部内容宽度，因此横屏手机不会仅因宽度大就变成平板，平板里的窄面板也会收回尺寸增量。

## 用数字推演一次高度预算

以下是教学数字，不是项目设计值：父级给内容区 600 个逻辑像素，高度已排除外层安全区；固定按钮区占 64，正文与插画最低需要 440，三段间距最小共 36。

```text
内容预算 = 600 - 64 = 536
最低需求 = 440 + 36 = 476
可继续分配给留白的空间 = 60
```

现在键盘出现，父级只给 420：内容预算变成 356，低于最低需求 476。此时继续压缩留白无济于事，应由页面选择重排或滚动，保留操作可达。这里不能在已经无限高的滚动内容内部再计算“屏幕剩余高度”。

## 一个最小的布局片段

下面是教学 `build` 返回值片段，需要 Flutter widgets 导入以及外部定义的 `content`、`closeButton`；不是可独立运行的 App，也不是通知栏源码副本。

```dart
Row(
  children: [
    Expanded(child: content),
    closeButton,
  ],
)
```

`Row` 先为非弹性关闭控件布局，再把剩余宽度交给 `Expanded`。这只决定 `content` 的预算；内容里的文字如何换行或滚动，仍由内容自身决定。父级本身窄到连关闭控件都放不下时，这段代码也不能保证不溢出。

通知栏进一步在弹性区内使用 `SingleChildScrollView` 和带最小宽度的 `ConstrainedBox`：内容能放下时保持分布，超宽时只滚动这一部分。不要机械地在横向滚动内部加入横向 `Expanded`，那里可能没有有限剩余宽度可分配。

## 最少源码阅读顺序

1. `lib/app/widgets/app_adaptive_layout.dart`：读 `AppLayoutInfo`、`AppAdaptiveLayout` 和 `AppFlexibleGaps` 的职责注释。
2. `lib/app/besideyou_adaptive_metrics.dart`：跟踪 `tabletFraction` 的窗口短边和内容宽度。
3. `lib/app/pages/home/home_notification_center_bubble.dart`：只读 `_HomeNotificationCenterHeader`。

停止点：能画出“固定关闭按钮 → 剩余宽度 → 局部滚动”的三层关系即可。共享工具内部算法不需要在本轮全部展开。

## 预测题与反例

平板窗口宽 1024，但通知面板宽 360。用窗口宽度计算标题字号，并设置标题区宽 900，会发生什么？

<details>
<summary>展开答案与理由</summary>

字号会按比实际面板更大的空间选择，900 的期望宽度仍受到 360 父约束限制。两项错误不会互相抵消，反而增加拥挤或溢出的可能。应读取面板约束，再决定内容尺寸。回看上面的输入表，区别窗口与父级预算。

</details>

如果界面没有 overflow 日志，是否可以认为布局通过？

<details>
<summary>展开答案与理由</summary>

不可以。文字可能被裁掉，按钮可能滚出首屏，点击区可能缩小。需要检查阅读与操作结果，不能只检查框架是否报错。测试也应保护关闭按钮可达、字号放大后内容可读等边界，而非冻结全部颜色和间距。

## 练习与完成标准

在独立练习页中做“长标题＋状态动作＋关闭按钮”，输入三组约束：360 宽手机、700 宽窗口里的 360 宽面板、横屏短高度；再开启两倍字号。观察关闭按钮是否固定、内容是否仍可读、滚动是否只发生在预定区域。这是待完成的视觉练习，本次未创建或运行该页面。

完成标准是能说明每一层的约束来源，解释为什么选局部滚动，并给出一个仍会失败的极端输入。实际项目 UI 改动仍须遵循设计与授权边界。

可迁移的经验：先确定固定区域、可变内容和退让顺序，再选择 Widget。面试讲述可以围绕“我如何定位父约束、设计最小反例、验证操作可达”展开；只有实际参与后才将案例描述为个人成果。
