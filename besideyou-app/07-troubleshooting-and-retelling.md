# 07｜把数据流用于排障，也用于讲清自己的开发

[专题入口](README.md) · [提交证据](../evidence/app-contributions.md) · [源码地图](../evidence/app-source-map.md)

这章把前六章变成可用的工作方法。案例基于同一份 2026-09-21 源码快照推演，没有新增运行验证；具体机制和源码指纹继续放在原章节与 evidence，不在这里建立第二套产品合同。

## 1. 一次排障先写五个格子

```text
触发条件 → 数据从哪来 → 最后正确点 → 第一个错误点 → 可核对证据
```

“最后正确点”是你已经确认输入或状态仍正确的地方；“第一个错误点”是它经过下一步后第一次不符合预期的地方。夹住这两点，才有足够理由定位修改范围。

例如：用户升级返回仍是灰色 Paw。不要先把按钮颜色改掉，先按[Home 第 9–10 节](03-home-data-flow.md)核对返回 Future、身份、强制 revalidate 和新队列。

| 已知事实 | 下一步看哪里 | 暂时不能推出什么 |
| --- | --- | --- |
| View Plans 已关闭 | `onViewPlans` 是否到此刻才完成 | 购买已经成功、权益已经生效 |
| Home 发起 revalidate | 是否同账号、同 queue，使用哪个 pet 上下文 | 服务端返回必然 ready |
| 新队列返回 | 生命周期、canEnter、有效档位和会员投影 | 只有“请求成功”就应换 Paw |
| 新结果被 controller 接受 | Root 的 Basic 判定与 UI 映射 | 视频已经可以立即出帧 |

如果第二格是第一处不正确，排障在回调或请求所有权；如果第三格就仍是 Basic，先查真实返回和业务合同。两种问题不能用同一种“强制显示已升级”修补。

## 2. 四个常见症状，一次只沿一条链

| 症状 | 按顺序检查 | 先打开哪篇 |
| --- | --- | --- |
| 加载已 100%，胶囊仍存在 | `statuses` 是否还保留 entry → materialize 是否返回 → owner 是否仍有效 | [Home](03-home-data-flow.md) |
| 换宠后背景与视频不对应 | snapshot/runtime 身份 → candidate 是否就绪 → dependencies/poster/背景是否同批发布 → 旧图片回调资格 | [Portrait 舞台](04-portrait-stage-and-runtime.md) |
| 按住够久却没教学成功 | 触区和资源是否支持 → pointer 是否被当前 Host 接受 → 观察是否为当前 TouchHold 且 playing → 有效计时是否被取消 | [触摸教学](05-touch-guide-and-progress.md) |
| 本地总进入升级页 | 入口文件 → Mock 开关 → Mock 强更值 → 对应 loader/gate | [本地入口](06-local-mock-and-real-entry.md) |

这里列的是检查顺序，不是断言你设备当前一定有这些问题。不要把一个假设原因写成已复现结论。

## 3. 三个打断时序，练会后比背类名更有用

### A. 一个请求还没回来，又来了一个新请求

在纸上写 A 请求和 B 请求。让 B 先回来，A 后回来；分别标出请求 generation 和可写共享状态的判断点。

解释时要明确：A 的 Future 可以完成，但它不一定能覆盖 controller 的当前快照。取消网络和禁止发布旧结果是不同动作。

### B. 宠物从 A 切 B，再切回 A

画三次 attachment/runtime 身份。最后一次 petId 又是 A，不表示第一次 A 的图片加载或播放回调能直接采用；还要看该轮 dependencies、entry 或 generation。

这是为什么只比较业务 id 有时不够。哪一层用哪一层的身份，回到第 04–05 章的真实检查，不把所有代次合成一个万能全局整数。

### C. 教学正在读本地进度，用户切换账号

先标记读取属于账号 X，再让当前账号变成 Y。X 的结果晚到时，应该先核对 owner；不能拿它决定 Y 是否需要教学。

完成教学的内存状态与持久化成功也要分开。存储失败时页面怎样继续、重启后是否可能再教，以[教学进度章节](05-touch-guide-and-progress.md)说明的真实失败路径为准，不能只看到一次成功提示就宣称跨重启已保存。

## 4. 基础知识要跟着问题用

| 你说的工程现象 | 实际需要的基础 |
| --- | --- |
| 套餐页回来后再刷新 | `Future`、`await` 与 route 返回值 |
| 页面没销毁但已经不是原宠物 | `State` 存活与业务身份不是同一条件 |
| 胶囊不会随网络列表跳动 | 稳定 id、当前数据投影与本地顺序分工 |
| 进度未知时不显示假数字 | nullable 值表达“未知”，与 0 区分 |
| 背景不因为重复 build 就重新抖动 | Widget/State、异步图片提交与播放器资源生命周期 |
| 请求 Hold 不直接完成教学 | 命令、回执、实际播放观察与业务计时分层 |
| 教学账号内跨宠物共享 | 持久化 key 的业务作用域 |
| Mock 继续走正式 DTO | 接口、依赖注入与外部依赖替换 |

能够把右边的概念用左边的真实经历解释出来，才算把基础和项目连起来；只记住英文名不够。

## 5. 一段可自行修改的项目介绍

下面是基于提交范围的表达草稿。真实发现过程、团队协作与设备结果要由你补充，不默认替你编造。

> 我在 BesideYou 手机 App 主要做了 Home 与 Portrait 体验相关的开发。Home 部分把服务端的宠物资格和本机资源准备分开，提供多宠准备列表、可确定的进度与失败重试，并补齐 Basic 用户从套餐页返回后的队列复验。Portrait 部分完善背景、画幅和触摸对应关系，接入实际播放观察来控制长按教学，再将教学完成事实按账号持久化。实现时重点处理等待期间切宠、离页、换账号导致的旧回调失效。另外维护本地 Mock 入口，便于观察客户端流程。

这段没有性能收益数字、线上规模或独立完成整套 App 的声明。若要添加“减少多少失败/卡顿”，先补同版本、同设备、同场景的前后证据。

### 展开 Home 案例：推荐顺序

1. **用户问题**：服务端已准备好，手机仍要下载，用户需要知道正在准备哪只宠物。
2. **数据分工**：queue 给资格，prewarmer 给本机状态，Root 组合，Shell 管稳定顺序和展开行为。
3. **具体难点**：未知 Content-Length 不能造百分比；比例 1 也不等于 materialize 完成。
4. **失败恢复**：失败项保留 Retry；账号或版本替换后旧结果不再发布。
5. **另一入口**：Basic 去套餐页后，等 route 关闭再 revalidate；不能从“用户打开过套餐页”推断权益成功。
6. **证据**：列对应提交、测试意图与本次未执行边界。

### 展开教学案例：推荐顺序

1. **用户动作**：首次有效教学要求按住可互动区域。
2. **请求与观察**：发送 TouchHold 不算完成，计时要有匹配的实际 playing 观察。
3. **中断**：松手、Cancel、可见性、attachment 或账号变化需要按真实 controller 处理。
4. **资源**：教学动作来自可播放的 `middle.base`，不是看到中间区域就假设资源存在。
5. **持久化**：完成事实是账号级，跨宠共享；读取和写入属于捕获的账号上下文。
6. **边界**：共享层提供观察与覆盖接缝，App 持有教学文案、时长和完成记录。

## 6. 自测：这三句话哪里越界

<details>
<summary>“接口已经成功，所以升级回来我直接把 Paw 改成可进入。”</summary>

缺少业务判定。要用当前账号、当前宠物的新队列和会员投影决定入口，而不是只看 HTTP 成功或套餐路由返回。

</details>

<details>
<summary>“测试给了 isPlaying=true，因此证明这台手机已经流畅播放。”</summary>

把测试输入和物理观察混在一起。测试能验证消费该观察的业务状态机，不能单独证明原生解码、屏幕出帧或真实操作流畅。

</details>

<details>
<summary>“我加了 generation，所以旧下载会立刻停止，服务端也不会再处理。”</summary>

夸大了代次检查的作用。generation 通常控制结果采纳或后续动作资格；是否取消实际 I/O 要看实现，已接受的服务端操作也不会因此自动撤销。

</details>

## 7. 留给自己的复盘模板

```text
用户动作：
所属提交/模块：
入口文件与方法：
输入对象与业务身份：
立即变化的状态：
等待的工作：
等待期间可能出现的打断：
结果回来后的资格检查：
失败后保留的数据与重试入口：
最后正确点 / 第一个错误点：
已确认的证据层：
尚未确认的层：
```

任选本专题的一条链填一次即可。无需把整套 App 通读完才开始复盘；先把自己改过的一个动作解释完整。
