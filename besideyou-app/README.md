这一组材料从用户动作开始，解释数据从哪里来、哪个对象作决定、界面何时变化，以及失败后怎样恢复。01–07 保留原有提交范围导读，08–13 从后续项目更新提炼可迁移的 Flutter 能力。

01–07 的具体提交、去重办法和来源日期保留在[原贡献证据](../evidence/app-contributions.md)。08–13 按项目难点选题，使用[独立来源快照](../evidence/app-october-source-map.md)，不作个人作者或负责范围认定。

## 两条贯穿全篇的线

```mermaid
flowchart LR
  A[用户选择宠物] --> B[Home 队列中的业务资格]
  B --> C[Space 快照与资源准备]
  C --> D[Portrait 舞台和共享播放器]
  D --> E[触摸请求]
  E --> F[匹配的播放观察]
  F --> G[教学状态与账号进度]
```

这是阅读地图，省略了路由、错误和生命周期分支；每一条箭头的条件在对应章节展开。

**数据线**追问输入、转换、持有者、输出。**时间线**追问立即发生什么、等待什么、等待期间哪些事会让结果过期。只有两条线一起看，才能解释“接口已经回了，页面为什么还不能进去”。

## 怎样使用源码入口

正文保留源码中的 English identifiers，引用跳转到知识库内的[源码索引](../evidence/app-source-map.md)。索引给出相对于 App checkout 的文件、符号和来源指纹；不要求公开仓库携带私有项目源码。

先按每章的最少文件顺序阅读，追到该章的停止点即可。不要为了理解一次长按，先读完所有登录、支付和原生视频代码。
