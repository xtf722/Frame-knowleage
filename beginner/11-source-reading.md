# 11：大项目里，一次只读一个动作

[上一课：定时器与监听](10-timers-listeners.md) · [课程目录](README.md)

本课不增加 Dart 语法。先能完成前面几课的小例子，再练“哪些代码这次需要读，哪些可以先跳过”。

## 第一步：把任务改写成一句用户动作

太大的起点是“读懂 Wi-Fi 模块”。把它缩成：“用户点击一个网络后，哪个函数先收到这个动作？”

你现在只要找到入口和下一步调用。路由、权限、扫描、重连、心跳都不需要在这一轮同时展开。

每轮给自己一个阅读预算：一个问题，一个生产文件，一个相关测试文件。找到了需要第三个文件的疑问，就记下来，留到下一轮。

## 第二步：把未知函数当成有说明的盒子

原创教学片段：

```dart
Future<void> refresh() async {
  if (loading) return;
  final items = await repository.loadItems();
  if (!mounted) return;
  setState(() {
    photos = items;
  });
}
```

假设 `loading`、`photos` 和 `repository` 已声明。本片段只用于读法训练，不是完整防重入实现：它没有把 loading 设为 true。

第一次只做四个标记：

| 标记 | 这里是哪句 | 我要读懂什么 |
| --- | --- | --- |
| 入口与条件 | `refresh`、`if (loading)` | 谁触发它，什么情况提前结束 |
| 等待 | `await repository.loadItems()` | 输入是什么，完成后得到什么类型 |
| 资格检查 | `if (!mounted)` | 等待后接收者是否仍存在 |
| 修改与显示 | `photos = items`、`setState` | 改了哪个字段，界面从哪里读取它 |

此时先把 `loadItems()` 当作“返回照片列表的异步方法”。只有本轮问题涉及下载错误或返回的数据时，才进入 repository 的实现。

**预测 1：需要读懂 HTTP 每个细节，才能解释上面的四个标记吗？**

<details>
<summary>展开答案与原因</summary>

不需要。先查方法声明里的参数与返回类型，确认它会交回怎样的列表。内部机制可以稍后补；你不能据此声称“加载一定成功”或“列表一定完整”，那是下一层需要核对的事实。

</details>

## 第三步：用一张小卡片留下自己的理解

不要复制整段源码，只写：

```text
问题：点击后为什么换照片？
入口：文件名 + 方法名
输入：当前索引/列表/设置中的哪些值
条件：什么时候提前return
变化：改哪个字段
后续：谁读取新字段或收到通知
还没读：本轮先当作盒子的那个方法
```

公开笔记只写相对路径与必要符号，不粘贴真实设备、凭据或私有服务地址。

## 第四步：用测试问一个具体问题

现有专题会列出测试文件和测试名。打开之后先找：

1. 构造了什么输入，例如两张照片或一个假网络服务。
2. 执行了什么动作，例如点击、等待或完成一个 Future。
3. `expect` 检查了什么结果，例如当前文字或调用次数。

先不用学会编写测试框架。把 `expect(actual, expected)` 读成“检查实际结果是不是预期”就能开始阅读。真实测试可能有更复杂的 matcher，卡住时只查当前那一个。

**预测 2：某个测试调用了 `controller.start()`，能据此判断真设备已经联网吗？**

<details>
<summary>展开答案与原因</summary>

不能。要看注入的依赖是否是假实现、断言检查的是请求次数还是设备网络。测试名和调用动作不能自动证明实际硬件效果。

</details>

从 Moment 短导读选一个自动换页测试，写下“输入、动作、预期”各一句。读不懂的部分只记录最前面的一个，不一次收集十几个名词。
